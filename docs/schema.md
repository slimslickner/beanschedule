# Schema

> Generated by `beanschedule docs`. Do not edit by hand.

Every `custom "schedule"` directive verb, metadata key and reserved value the engine understands.

## Directive verbs

### `new`

Defines an immutable rule. Its recurrence generates the nominal occurrence dates, and the matched account and matching hints are metadata. The other-side posting accounts are declared separately, with `custom "schedule" "posting"`.


| Argument | Kind | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | The schedule's stable identifier. |


Metadata: `rrule`, `start`, `end`, `payee`, `narration`, `match-account`, `match-payee`, `match-amount`, `amount-mode`, `amount-tolerance`, `amount-min`, `amount-max`, `window-before`, `window-after`, `method`, `rate`, `term`, `balance-from-ledger`, `escrow`, `principal-account`, `interest-account`, `escrow-account`.

### `posting`

Declares one other-side posting of a schedule. A rule may declare several, in the order they should appear; together they must carry the occurrence's split. Any metadata besides `amount` and `narration` is copied verbatim onto the posting, so conventions such as `contribution-year` are preserved. A posting's own date is ignored; the occurrence's date is used.


| Argument | Kind | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | The schedule the posting belongs to. |
| `account` | string | yes | The other-side account to post against — not the matched account, which is named by the rule's `match-account`. |


Metadata: `amount`, `narration`.

### `skip`

Skips one nominal occurrence (an iCalendar EXDATE). The directive's own date is the skipped nominal date. Deleting it reopens the occurrence.


| Argument | Kind | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | The schedule whose occurrence is being skipped. |


Metadata: none.

### `move`

Moves one nominal occurrence to another date (an iCalendar RECURRENCE-ID). The directive's own date is the original nominal date and the argument is the new date. Deleting it reopens the occurrence.


| Argument | Kind | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | The schedule whose occurrence is being moved. |
| `date` | date | yes | The date the occurrence moves to. |


Metadata: none.

## Metadata keys

| Key | Kind | Required | Default | Applies to | Meaning |
| --- | --- | --- | --- | --- | --- |
| `rrule` | rrule | yes | — | new | The RFC 5545 recurrence rule (without a `DTSTART`) that generates the nominal occurrence dates, e.g. `FREQ=MONTHLY;BYMONTHDAY=15`. The rule's phase comes from `start`, not from the DTSTART text. |
| `start` | date | yes | — | new | The first nominal date and the anchor the interval is measured from, e.g. `2026-01-15`. It retains the rule's phase, so a moved statement day does not shift the series. |
| `end` | date | no | — | new | The last nominal date, inclusive. Omit for an open-ended series. |
| `payee` | string | no | — | new | The payee written onto a matched or forecast transaction, overriding the imported one. |
| `narration` | string | no | — | new, posting | The narration written onto a matched or forecast transaction, or onto a declared posting. |
| `amount` | decimal | no | — | posting | A declared posting's signed amount, as it should appear in the transaction. All but one posting must set it; the one that omits it is left for Beancount to balance. |
| `match-account` | string | yes | — | new | The single account an imported transaction must post to in order to match this schedule, e.g. `Assets:Bank:Checking`. |
| `match-payee` | string | no | — | new | A regex (case-insensitive) the imported payee must match. Omit to ignore the payee. |
| `match-amount` | decimal | no | — | new | The reference amount, with the sign of the matched posting. Used by the `exact` and `approx` amount modes. |
| `amount-mode` | string | no | — | new | How `match-amount` is judged: `exact`, `approx`, `range` or `any`. Defaults to `any` when no amount hints are given, else `exact`. |
| `amount-tolerance` | decimal | no | — | new | The ± bound for the `approx` amount mode. Requires `match-amount`. |
| `amount-min` | decimal | no | — | new | The lower bound for the `range` amount mode. Requires `amount-max`. |
| `amount-max` | decimal | no | — | new | The upper bound for the `range` amount mode. Requires `amount-min`. |
| `window-before` | integer | no | — | new | How many days before a nominal date a transaction may post and still consume it. Defaults to the ledger-wide window. |
| `window-after` | integer | no | — | new | How many days after a nominal date a transaction may post and still consume it. Defaults to the ledger-wide window. |
| `method` | string | no | — | new | How a loan payment is split: `static` (from `term`/`rate`) or `balance-from-ledger` (walk forward from the liability balance). |
| `rate` | decimal | no | — | new | The annual interest rate for amortization, e.g. `0.0675` for 6.75%. |
| `term` | integer | no | — | new | The loan term in whole months, for `static` amortization. |
| `balance-from-ledger` | boolean | no | — | new | TRUE selects `balance-from-ledger` amortization, reading the liability balance from `principal-account`. An alias for `method: "balance-from-ledger"`. |
| `escrow` | decimal | no | — | new | A fixed escrow amount added to each amortized payment. |
| `principal-account` | string | no | — | new | The liability account holding the loan principal, for amortization. |
| `interest-account` | string | no | — | new | The expense account the amortized interest posts to. |
| `escrow-account` | string | no | — | new | The expense account the escrow portion posts to. |


## Reserved values

| Value | Key | Meaning |
| --- | --- | --- |
| `exact` | `amount-mode` | The matched amount must equal `match-amount` exactly (or within the currency's display precision). |
| `approx` | `amount-mode` | The matched amount must be within `amount-tolerance` of `match-amount`. |
| `range` | `amount-mode` | The matched amount must be within `amount-min` and `amount-max`. |
| `any` | `amount-mode` | The amount is not checked; only account, payee and date matter. |
| `static` | `method` | Amortization from `rate`, `term` and the rule's `start`, so the split depends only on the occurrence's position in the series. |
| `balance-from-ledger` | `method` | Amortization walks forward from the liability balance in `principal-account`, so the split follows the ledger. |
