# Schema

> Generated by `beanschedule docs`. Do not edit by hand.

Every metadata key and reserved value the engine understands. A schedule is a real Beancount transaction carrying an `id` and an `rrule`; its postings carry the split. Any metadata the engine does not own — and the transaction's tags and links — are carried onto the transaction that reconciles it.

## Metadata keys

| Key | Kind | Required | Default | Applies to | Meaning |
| --- | --- | --- | --- | --- | --- |
| `id` | string | yes | — | schedule | The schedule's stable identifier, unique across the schedules file. The matched transaction is tagged `schedule: "<id>"`. |
| `rrule` | rrule | yes | — | schedule | The RFC 5545 recurrence rule (without a `DTSTART`) that generates the nominal occurrence dates, e.g. `FREQ=MONTHLY;BYMONTHDAY=15`. The rule is anchored at the transaction's date. |
| `end` | date | no | — | schedule | The last nominal date, inclusive. Omit for an open-ended series. |
| `match-account` | string | no | — | schedule | The account an imported transaction must post to in order to match this schedule, e.g. `Assets:Bank:Checking`. Defaults to the first balance-sheet posting. |
| `match-payee` | string | no | — | schedule | A regex (case-insensitive) the imported payee must match. Omit to ignore the payee. |
| `amount-tolerance` | decimal | no | — | schedule | The ± bound on the matched amount. Setting it selects approximate matching; without it the amount must be exact. |
| `window-before` | integer | no | — | schedule | How many days before a nominal date a transaction may post and still consume it. Defaults to the ledger-wide window. |
| `window-after` | integer | no | — | schedule | How many days after a nominal date a transaction may post and still consume it. Defaults to the ledger-wide window. |
| `method` | string | no | — | schedule | How a loan payment is split: `static` (from `term`/`rate`) or `balance-from-ledger` (walk forward from the liability balance). Defaults to `static`. |
| `rate` | decimal | no | — | schedule | The annual interest rate for amortization, e.g. `0.0675` for 6.75%. |
| `term` | integer | no | — | schedule | The loan term in whole months, for `static` amortization. |
| `balance-from-ledger` | boolean | no | — | schedule | TRUE selects `balance-from-ledger` amortization. An alias for `method: "balance-from-ledger"`. |
| `escrow` | decimal | no | — | schedule | A fixed escrow amount added to each amortized payment. |
| `schedule-leg` | string | no | — | posting | On an amortized schedule's posting, names the leg: `principal`, `interest` or `escrow`. The posting's amount is a placeholder. |


## Reserved values

| Value | Key | Meaning |
| --- | --- | --- |
| `static` | `method` | Amortization from `rate`, `term` and the schedule's date, so the split depends only on the occurrence's position in the series. |
| `balance-from-ledger` | `method` | Amortization walks forward from the liability balance in the leg marked `principal`, so the split follows the ledger. |
| `principal` | `schedule-leg` | The posting receives the principal component of a payment. |
| `interest` | `schedule-leg` | The posting receives the interest component of a payment. |
| `escrow` | `schedule-leg` | The posting receives the escrow component of a payment. |
